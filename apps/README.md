# Benchmark Applications Documentation

This directory contains several benchmark applications used for gem5 full-system simulations. This document outlines what each application does, what prerequisites it needs, and how to run it.

## Quick Build (`compile_apps.sh`)

Use the bundled [compile_apps.sh](file:///media/pravesh/Storage/code/sims/modgarnet/apps/compile_apps.sh) script to build and automatically package all 4 benchmarks for either **x86** or **ARM**:

```bash
# Build for ARM (AArch64) and package into configs/doing/run_apps_arm.sh:
./apps/compile_apps.sh arm

# Build for x86 and package into configs/doing/run_apps.sh:
./apps/compile_apps.sh x86

# Clean builds:
./apps/compile_apps.sh clean
```

## 1. BTree (B-Tree Data Structure Benchmark)

**Description:**
Evaluates memory access patterns and TLB/Cache behavior during B-Tree traversals and insertions. It creates a B-Tree of a specified size and then performs a number of random lookups.

**Requirements:**
- The compiled `./BTree` executable.
- No external datasets required.

**How to run:**
```bash
# Usage: ./BTree <num_elements> <lookups>

# Smoke Test (Runs instantly)
./BTree 1000 100

# Large Test (Massive memory footprint, heavily stresses the TLB and Page Table Walker)
./BTree 10000000 1000000
```

## 2. GUPS (Giga Updates Per Second)

**Description:**
A standard memory benchmark that performs completely random memory accesses and updates. It is designed to measure the rate of random memory updates and is excellent for stressing the MMU (Memory Management Unit) and the hardware page walker, as almost every access results in a TLB miss.

**Requirements:**
- Source code is in `gups-app/gups.c`.
- Must be compiled manually if the executable is missing: `cd gups-app && gcc -O3 gups.c -o gups`

**How to run:**
```bash
# Usage: ./gups-app/gups <memory_in_GB>

# Large Test (Allocates 1GB of memory. Fits in a 2GB gem5 VM but consumes many pages)
./gups-app/gups 1
```

## 3. HashJoin (TPC-H Query 10 / Query 11)

**Description:**
Implements a database hash join operation. Given two database tables (a small relation and a large relation), it builds a hash table on the smaller relation and probes it with the larger one.

**Requirements:**
- Requires `.tbl` dataset files generated by the TPC-H database generator (`dbgen`).
- To generate the datasets (e.g., at scale factor 0.01):
  ```bash
  cd hashjoin/tpch-dbgen-master
  make
  ./dbgen -s 0.01
  # This generates customer.tbl (1500 rows) and orders.tbl (15000 rows)
  ```

**How to run:**
```bash
# Usage: ./hashjoin/query10 <hash_function> <small_table> <small_rows> <large_table> <large_rows> <hash_table_size> <run_id>
# Note: hash_table_size should ideally be a prime number.

# Smoke Test (Reads a tiny subset of the generated dataset)
./hashjoin/query10 murmur3 hashjoin/tpch-dbgen-master/customer.tbl 150 hashjoin/tpch-dbgen-master/orders.tbl 1500 17 1

# Large Test (Processes the full 0.01 scale dataset)
./hashjoin/query10 murmur3 hashjoin/tpch-dbgen-master/customer.tbl 1500 hashjoin/tpch-dbgen-master/orders.tbl 15000 16381 1
```

## 4. XSBench

**Description:**
A mini-app representing a key computational kernel of the Monte Carlo neutron transport algorithm. It focuses on the macroscopic cross-section lookup loop, which involves making highly random memory accesses into a massive energy grid. It is an excellent workload for testing memory bandwidth and TLB hit rates.

**Requirements:**
- The compiled `./XSBench` executable.
- No external datasets required (grid is generated in memory based on the `-s` size flag).

**How to run:**
```bash
# Usage: ./XSBench -s <size> -g <gridpoints> -p <particles> -l <lookups>

# Smoke Test (Very small grid, minimal lookups)
./XSBench -s small -g 100 -p 100 -l 100

# Large Test (Large cross-section grid, random jumps stress the TLB heavily)
./XSBench -s large -g 1000 -p 1000 -l 10000
```
